# 涟漪按音频特性分层 · Hana 落地方案

日期：2026-10-11。状态：**方案，尚未实现或部署**。

本轮按用户要求只读生产代码并写交接方案，后续由 Hana 完成实现。读取时为 `hana-simple` 分支、构建 `1003131651`；开始实现前重新核对工作区与构建号，保留其它正在进行的修改。

## 1. 用户已确认的方向

- 保持播放器现有封面环境色、歌词薄纱、柔和流光和细波纹的风格。早先示意中的明显蓝色光圈已被用户否定。
- 所有音频类型共用现有配色，**用形态、速度、余韵区分**，不按频段分配不同颜色。
- Bass 推动宽缓水面；瞬态敲击点出短促细波。合奏时叠在同一片水面里。
- 用户在可调示意中确认：**默认强度 1.6 倍差不多**。最终明确口头值是 `1.6`，不是交互状态里曾出现的 `1.65`。
- 调整条已经用于动效预览与选定默认值。生产主界面是否增加常驻滑杆尚未拍板，本轮先落地默认值，不据此重排控制条。

强度 1.6 是本次动效示意的视觉参考，不是音频增益；不得改变播放音量。以下检测阈值、半径、寿命与数量限制均为**工程建议起点**，需要真实曲目校准，不是用户逐项确定的参数。

## 2. 现状与应改的地方

主要入口：`ui/app.js` 的 `initRipples()`。

| 现有函数/状态 | 当前行为 | 建议变化 |
| --- | --- | --- |
| `attachAudio()` | `captureStream()` 副本 → Analyser → 零增益输出；FFT 4096、平滑 0.65 | 保持安全音频路径；为瞬态提取减少过度平滑 |
| `readSignal()` | 40–180Hz 能量超过滑动均值 1.28 倍，且间隔 >300ms，即落波 | 拆成持续低频包络与瞬态起音两路判断 |
| `drop()` | 所有输入都生成同一种约 3 秒波包 | 音频敲击使用专用短波；持续 Bass 不调用它 |
| `inject()` / `stepField()` | 高斯扰动、双缓冲波传播和阻尼 | 复用；增加受控的宽缓低频驱动 |
| `paintField()` / `ringPath()` / `draw()` | 现有柔和流光与四层透视环 | 保留画法；音频短波优先一主一辅两环 |
| `strength()` | 有词 0.32、无词 0.50，注入与绘制两处使用 | 区分原有场强与最终可见强度，防止倍率重复应用 |
| `audioLoop()` / `sync()` / `detachAudio()` | 采样、页面状态同步、换源释放 | 补齐新增检测状态的重置及隐藏/离屏时的停止与恢复 |

当前分析只有一个低频标量，Bass 换音与底鼓容易触发同一种波；中高频敲击没有独立判断。应改变的是**驱动方式**，不是重写一套彩色视觉引擎。

## 3. 动效行为

### 持续低频：宽缓流光

- 用平滑后的低频强度驱动已有高度场；主要表现为宽而柔的波面起伏，不附加清楚的落点、中心小闪圈或多层线圈。
- 注入范围比敲击宽，位置集中在封面附近，随布局计算可用区域，小幅缓慢游移。不要每次换音在全舞台随机换位置。
- 建议包络上升约 100–150ms、回落约 400–600ms。响应音乐的力度变化，不逐帧抖动。
- `driveBass(envelope, dt)` 应按实际经过时间推进并限制注入量/场能量；不要每帧无条件加固定能量，也不要仅靠 `drop()` 限频来伪装持续响应。
- 稳定低频可以维持轻微水面运动，但不能无限堆积；低频结束后自然收敛。30/60/120Hz 屏幕下的观感应接近。

### 瞬态敲击：短促细波

- 检测明显起音后产生短波，复用 `ringPath()` 的透视和轻微形变。建议一条主环、一条更淡的回声，寿命约 1.0–1.4 秒。
- 低频占比高的瞬态稍宽厚；中频起音更轻薄、退得更快。参数差异小而可感知即可，不必宣称辨认出了底鼓或军鼓。
- 建议明显音频波包同时不超过 3 组，密集音乐中大约每秒保留 1–2 次明显落波。短时间内的相近弱起音合并或跳过，避免满屏雨点。
- 起音位置集中在封面区域的一小片范围，不满场跳。强拍增加单次波的清晰度，优先于增加数量。
- 强度倍率只增加可见力度，不增加触发频率、环数或寿命。

### 高频与合奏

- 首轮不为踩镲生成独立波包。高频至多轻微影响已有细波的质感；只出现高频时也不需要硬凑新特效。
- 同一个瞬态同时出现在几个频段时，只产生一次敲击波。Bass 的连续场与该短波可以同时存在，但共享亮度/能量预算。
- 波纹仍在封面/薄纱之上、文字之下；歌词附近局部降低动效，不改歌词透明度，不让整屏随鼓点闪亮。
- 用实际歌词区矩形计算减弱区域，并在布局/尺寸变化后更新，避免把独立窗的固定左右比例套进长卡和窄卡。

## 4. 音频提取建议

### 保持原播放路径

沿用 `<audio>.captureStream()` 另拷一路分析，副本零增益，不与原声叠加。**绝不改成 `createMediaElementSource()`**；仓库已有跨源静音且不可逆的实测记录。

跨源、不支持捕获或没有音轨时，播放继续，按现有指针/低频呼吸效果降级。不得把模拟节拍当成真实音频数据。

### 持续能量与起音分开处理

建议先复用一个 FFT 4096 的分析器：将频谱内置平滑降至约 0.1–0.2，再自行平滑 Bass 包络。实际起音反应仍明显迟钝时，才考虑增加 FFT 2048 的瞬态分析器；不要降低持续低频分析的频率分辨率。

分析采样建议约 30Hz，数组预分配复用。频段建议起点：

| 特征 | 频段建议 | 用途 |
| --- | --- | --- |
| 低频能量 | 40–180Hz | 宽缓流光包络；低频瞬态的重量 |
| 中频增长 | 180–2000Hz | 补足低频判断遗漏的敲击起音 |
| 高频增长 | 2000–8000Hz | 限量修饰/辅助判断，不单独下雨 |

- 能量继续按功率求和/平均后开方，不能直接把负 dB 值相加当能量。
- 起音可用相邻帧频谱的**正向增长（spectral flux）**，结合快慢包络差和最低有效电平；不要只凭某个频段的大小认定乐器。
- 阈值按每个频段近期背景能量自适应，并保留静音门限、分母下限与非有限值处理，避免很安静时误放大噪声。
- 对几个频段的同次起音做合并，再统一走事件冷却、弱事件抑制和数量预算。
- 歌声辅音、钢琴换音等也会形成瞬态；这是音频特征到动效的艺术映射，不是乐器分离。置信度不足时优先少画一圈。
- 换曲、seek、分析链重建后清掉上一帧频谱和自适应统计，建议留约 250–500ms 预热，避免突然全亮的第一帧被误当强鼓点。

可参考 [librosa 起音强度说明](https://librosa.org/doc/0.11.0/generated/librosa.onset.onset_strength.html) 与 [Web Audio 分析器契约](https://www.w3.org/TR/webaudio-1.0/#AnalyserNode)。只借鉴方法，不为前端引入 Python、librosa 或新运行时依赖。

## 5. 1.6 倍如何接线

设 `visualGain = 1.6`，以此前较淡的示意为 `1.0` 的视觉参考，同时保留有词/无词的强度关系。

**不要只把当前 `strength()` 返回值乘 1.6。** 当前 `drop()` 的 `inject()` 已乘一次 `strength()`，`paintField()` 又乘一次。这样短波的流光部分会近似放大 `1.6 × 1.6 = 2.56` 倍，线环却大致只有 1.6 倍，容易变得比用户选定的更亮。

推荐实现：

1. 保留 `baseStrength()`：有词 0.32、无词 0.50，用于原有输入力度与场能量控制。
2. 在最终绘制阶段统一应用 `visualGain`，在流光、主环和回声的最终 alpha 上只乘一次，再限幅。中心小圈若保留，也需计入同一预算。
3. 新 Bass 驱动与短波的输入参数分别校准；不要把 visualGain 同时施加到输入力、最终 alpha、环数和半径。
4. 视觉倍率增加时保留局部读词减弱与 alpha 上限，防止多个波叠加成一片亮膜。

预览里旧的 `strength()` 全局乘数、静态预览注入值以及有些路径的二次放大都属于示意写法，不应原封不动当作生产参数。目标是用户选定的“比原先明显一点、仍然安静”的 1.6 档观感。

需要继续校准时，沿用一个共用滑杆：`0.5–3.0`、步长 `0.05`、默认 `1.6`，显示倍率，拖动实时更新；不改变音乐播放或重建分析链。若以后决定进生产设置，使用 Hana SDK 存储并在 SDK 就绪后读取，不直接用 localStorage。

## 6. 生命周期与资源

- 暂停后沿用约 400ms 收敛，再停止绘制与分析；恢复时正确重启，不能重复绑定。
- hidden、离屏、reduced-motion 应同时停绘制和分析调度；恢复时重新建立时间基准，清理过期起音历史，避免补发一串积压鼓点。
- 当前 `audioLoop()` 即使 `blocked()` 也会在尾部继续排 rAF，不能将其当作已经完成“隐藏时停止”的保证；本轮应把分析调度一起接入可见性同步。
- 截图冻结不推进波龄、不改变像素，也不向场里继续注入；解冻后不补算隐藏期间的波。
- 分析链记录本次捕获流、source、analyser 与零增益节点；换源、销毁、拆窗后按所有权释放，异步 attach/resume 要有代次检查，过期结果不可挂回新歌。
- 真实音频可读时停掉随机呼吸波，静音不产生“音乐驱动”的新波；采样可继续以发现声音恢复，绘制在场收敛后停止。捕获不可用时保留原先降级行为。
- 保持 DPR 上限 2、网格上限 260×160 与有限波包数量。不要为了较强的观感提高画布分辨率或引入封面逐像素折射。

## 7. 验收要求

保留现有 `tools/verify-ui.mjs` 验收，按最新工作区的实际断言总数运行，不用旧交接里的固定计数替代结果。

现有 `motion-ripple-reactive-to-audio` 主要通过 `rippleAudioPoke(0.08)` 注入低频标量，只能证明“能触发一个波”，不能证明 Bass/瞬态分开检测正确。应补以下有意义的测试：

- 用**真实同源合成音频夹具**经过 captureStream/FFT：持续 80Hz 低音能维持宽缓场，预热后不持续生成短波；重复短脉冲产生有限细波；中频噪声敲击能被现有低频门限之外的起音路径识别。
- 同样总音量的持续信号与短脉冲，得到不同形态；稳态纯音、静音不会周期性伪造鼓点。
- 密集脉冲经过事件合并后满足音频波包预算；连续低频长播不会场能量越来越大。
- 强度调整只改变动效，实际音频音量、波包触发计数不随倍率变化。
- 暂停/恢复、换曲/seek、隐藏/离屏/reduced-motion、截图冻结与跨文档拆窗恢复均无积压突发、重复调度或运行时错误。
- 同源 → 跨源 → 同源换曲，始终正常出声，可读音频恢复后能重新响应。保留 `reactive-uses-captureStream-not-mediaElementSource` 守卫。

真机至少试听：持续 Bass 曲目、明显底鼓曲目、敲击/踩镲密集曲目、钢琴/人声主导曲目、纯音乐。检查 465×930 长卡、312px 窄卡、1040×780 窗口和矮窗，覆盖浅深主题、有词/无词与不同封面。

目视验收重点：能看出“水面在托住低音，短波在回应敲击”，歌词阅读不被抢走；主波源不满场跳，高潮仍有层次，安静段确实收敛。不要只用截图替代试听与播放中观察。
