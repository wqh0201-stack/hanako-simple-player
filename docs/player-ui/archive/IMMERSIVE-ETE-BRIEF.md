## 1. 工程目标

把当前完整播放器改成沉浸播放页，同时修正横版封面挤压歌词列的问题：

1. **顶部 edge-to-edge（ETE）**：封面与环境色延伸到窗口顶部，宿主窗口控件悬浮在背景上。
2. **隐藏标题栏应用名**：去掉截图左上角的「小花音乐播放器」文字；保留宿主的钉回、置顶、最小化、全屏、关闭等操作，应用目录中的注册名称保留。
3. **底部背景贯通**：封面与环境色延伸到窗口底部，播放控制条成为覆盖在背景上的一层毛玻璃。
4. **按窗口进出显隐底栏**：播放时允许隐藏；暂停、搜索或正在操作时保持显示。移出整个播放器窗口后约 5 秒隐藏，进入或点击窗口立即恢复。
5. **搜索恢复主题界面**：搜索区域和底部控制条恢复当前宿主主题色，控件常驻；不使用沉浸播放页的玻璃底栏。
6. **统一歌词阅读位置**：同样大小的窗口下，横版、方形、竖版封面共用同一条标题／歌手／歌词阅读轴，封面比例不再把文字列推向右缘。

用户明确：**本轮不需要考虑触屏交互**。桌面鼠标与键盘的可操作性仍要保留。

## 2. 用户已经确认的交互规则

### 2.1 窗口边界与计时

边界是**整个播放器窗口**，包含播放画面；不是底部控制条或歌词列。

| 事件／状态 | 行为 |
| --- | --- |
| 鼠标进入窗口 | 立即显示底栏，取消隐藏倒计时 |
| 点击窗口 | 恢复底栏，取消隐藏倒计时；避免隐藏控件误吃点击造成跳进度等意外 |
| 窗口重新获得焦点 | 恢复底栏（含键盘切回） |
| 播放中，鼠标离开窗口 | 开始约 **5000ms** 倒计时，到时按钮与玻璃背景一起淡出 |
| 鼠标一直留在窗口里，即使静止 | 控件保持显示；**不叠加窗口内静止自动隐藏** |
| 暂停／停止 | 底栏保持显示 |
| 搜索打开或正在收起 | 主题色底栏保持显示 |
| 正在拖进度、调音量、操作菜单／弹窗、歌词对齐等 | 保持显示，不让倒计时打断操作 |
| 操作结束，鼠标仍在窗外，且允许隐藏 | 从操作结束重新计满 5 秒 |

键盘焦点仍在底栏或浮层内时保持可见。队列／菜单展开时保留可用控制条。
计时结束前必须重新检查允许隐藏的条件，防止期间暂停、打开搜索或开始操作后仍被旧定时器藏掉。

### 2.2 动效与几何

- 按钮与底部玻璃作为一个视觉工具层显隐。
- 淡出约 200ms，恢复更快一些；具体曲线与时间沿用现有动效语言，可在真机微调。
- 控件显隐**不改变封面尺寸、裁切、歌词位置或页面高度**。
- 隐藏状态不残留透明的可点击按钮挡住画面。恢复入口保持有效，键盘操作也能唤回。
- `prefers-reduced-motion` 下缩减动效。

### 2.3 搜索与无封面

- 搜索界面恢复现有宿主主题色，底部播放操作始终可用。
- 搜索退出动画完整结束后再恢复沉浸，不能只看到 `data-search=0` 就立刻变透明。
- 搜索界面仍隐藏标题栏应用名。
- 无封面时建议保留现有主题色兜底和常驻底栏，不让没有纹理的背景硬做玻璃。
- 所有主题色继续跟随 Hana，不新增独立主题开关，不改已有控制按钮强调色体系。

## 3. 已确认的根因与宿主能力

### 3.1 顶部 ETE 是宿主的正式能力

当前 manifest 的播放器卡声明仍为：

```json
{
  "cardForm": "flush",
  "titlebar": "solid"
}
```

Hana 官方契约规定：

- `cardForm: "edge-to-edge"`：内容填满包括顶部的整个卡体；宿主 Chrome 悬浮，标题默认隐藏。
- `titleMode: "hide"`：显式隐藏标题；应用注册名称与窗口操作仍可保留。
- 声明新形态或 `titleMode`，必须同时设置 **`minAppVersion >= "0.1017.0"`**。
- `titlebar` 是旧兼容字段。改用新形态时移除旧 `titlebar`，避免与新形态产生冲突。

建议配置方向：

```json
{
  "minAppVersion": "0.1017.0",
  "contributes": {
    "cards": [{
      "id": "player",
      "cardForm": "edge-to-edge",
      "titleMode": "hide"
    }]
  }
}
```

以上是**字段示意，不是替换整份 manifest**；其他既有字段全部保留。若主对话另有更高的最低宿主版本要求，以其为准。

只读检查还确认：宿主拆窗 renderer 同样使用卡片形态解析，透明标题栏采用顶部绝对定位，不占独立的实色标题带。因此截图中的拆窗有实现路径。
不需要为这件事另建 App 自有原生窗口，也不应在当前 iframe 里借用只适用于原生 App 窗口的 `hana.window` API。

上述是契约与代码依据，**尚未对本方案做真实宿主效果验收**。

### 3.2 横图把文字推右的根因

`ui/app.js` 的 `updateStageMetrics()` 当前计算：

```js
coverW = h * coverAR;
contentX = w * ratio;
contentX = Math.max(contentX, coverW * 0.72);
contentX = Math.min(contentX, w - 210);
```

歌名、歌手、来源、歌词共用 `--content-x`。
横图的 `coverW` 大，`coverW * 0.72` 把整个文字列推到右侧，最终只剩约 190px 的可读宽度。

用户对比图是同样约 910px 宽的窗口：

| 对比图 | 文字列起点（截图估算） | 表现 |
| --- | --- | --- |
| 横版封面「周杰伦－超人不会飞」 | 约 700px，窗口宽度约 77% | 标题末尾「飞」单独换行，歌词频繁折行 |
| 方形封面「雨爱（DJ版）」 | 约 466px，窗口宽度约 51% | 阅读列宽松，位置更接近窗口中部 |

ETE 使背景变高后，沿用上述公式会继续增大封面显示宽度，更容易推右文字。
**本工程必须把背景画幅与阅读列定位解耦**，不能只把底栏背景改透明。

## 4. 推荐实施结构

### 4.1 一个连续背景，两个前景模式

- 封面、环境色与必要的兜底晖开层覆盖完整播放器区域，形成一张连续的背景。
- 播放页的标题／歌词／涟漪维持各自职责；底栏作为玻璃工具层覆盖背景。
- 搜索页以主题色表面盖住背景，底栏恢复主题色。
- 背景尺寸不依赖底栏当前是否可见；隐藏控件不会触发布局重排。
- 封面与底栏下方的背景使用同一套尺寸和位置，避免两份封面分别缩放造成接缝。

最终 DOM 移动或背景容器拆分由实现者决定，保留全部既有 id／data 钩子。

### 4.2 阅读轴由窗口决定

- 标题、歌手、来源、歌词始终对齐到同一个阅读列起点。
- 宽窗以当前方图的阅读位置为基准，继续允许位置随窗口宽度平滑调整；不写死像素坐标。
- 封面比例不参与宽窗阅读列起点的推右规则。
- 横图可延伸到文字下方，通过现有薄纱／羽化保证可读性；不靠把文字挤到右边避开图片。
- 窄卡维持自身响应式布局，同样避免长横图留下过窄的文字列。
- 普通长标题的自然换行保留；不以缩小字号或强制单行解决列宽问题。

### 4.3 玻璃与浮层分开处理

- 毛玻璃包含适当的主题底色；`blur` 提供质感，底色保证按钮／文字对比度。
- 模糊只覆盖底部工具区域，隐藏后移除不必要的持续模糊开销。
- **不能随手给整个控制条加 `backdrop-filter`、`opacity` 动画或变换后就算完成**：这些会改变层叠关系。
- 现有音量浮层向上伸进舞台，必须继续高于队列／遮罩／搜索页。玻璃背景可用独立层；必要时将弹出层放进统一浮层容器，最终结构需实测。
- 顶部宿主按钮在亮／暗封面上的可读性另验；可以利用现有顶部渐变，宿主操作仍由宿主管理。

## 5. 开工前需真机确认的技术边界

1. **整个窗口的鼠标进出**：App 是 iframe。进入宿主顶部按钮区域可能表现为离开 iframe，却仍在同一个原生窗口里。须验证事件边界，区分覆盖层切换与真正出窗；按用户确认的“整个窗口”语义实施。若当前公开宿主接口不能准确表达，向主对话／Hana 汇报限制，不能悄悄改成“离开底栏 5 秒”。不读宿主私有 DOM，不造非公开窗口桥。
2. **宿主按钮自动隐藏**：本轮只承诺播放底栏自动隐藏。窗口关闭／最小化等按钮继续保留；是否有官方的悬停显隐由 Hana 核对，不自行隐藏宿主操作。
3. **卡片入口一致性**：完整播放器由 manifest 卡片入口加载；聊天工具返回的浓缩单曲卡在 `tools/play.js` 的 `details.card`，还有独立的形态入口。核对其行为，避免只改 manifest 就宣称所有入口一致。浓缩卡是否参与整套沉浸，由主对话按其已有产品形态确定，不强行套用完整播放器布局。
4. **已有卡片与新卡片**：宿主保留的旧 binding 可能有历史形态。新建卡片与已有卡片都要检查，尤其是拆窗／钉回后的样式与续播。
