# 歌词标题精简与手动匹配（LYRIC-MATCH-DONE）

2026-10-11。罐头需求（两条）：
① **标题精简**：自己提供一个动作，把标题精简后再去匹配 —— 比如 B站《下雨天》那种一堆杂词的标题，只留「下雨天」；
② **手动适配**：允许用户自己改关键词，让它能正确匹配到这首歌。

**已部署**，构建号 1003131637。改动落在 `ui/index.html` / `ui/standalone.html` /
`ui/style.css` / `ui/app.js` / `tools/verify-ui.mjs`。**未碰后端**（复用既有

## 1. 先厘清：这不是匹配算法笨，是喂进去的名字本来就是假的

动手前用真实数据（B站搜索结果，`opencli bilibili search`）验了三条假设，全部成立，
**并挖出比它们更靠上游的元凶**：

| # | 事实 | 证据 |
|---|---|---|
| ① 元凶 | 跨源兜底原样拿 `[title, author].join(' ')` 去搜 | 关键词实长：`【4K珍藏】南拳妈妈《下雨天》MV极致修复！（收录于2008年专辑《优の良曲 南搞小孩》） 郭总说` —— 拿这句去网易云搜「下雨天」必然空手。**搜索这一步就废了**，改 `pickLyricHit` 只治一半 |
| ② | B站曲目拿不到数字 id，前四条降级路全断 | 真 id 是 `BV11vG76xEnk`，`onlineIdOf()` 的 `^[a-z]+:(\d+)$` 与 `/music/go/(\d+)` 都取不到 |
| ③ | `author` 是 UP 主不是歌手 | 实测 `郭总说` / `JLRS-LeoFM` / `VV音乐局` / `4K音乐馆`，跟真歌手永远对不上 |
| ④ | 标题尾巴没清掉 | 旧 `normLyricTitle` 把首条清成 `南拳妈妈《下雨天》mv极致修复！`，跟库里「下雨天」谈不上相等 |

**关键印证**：用干净关键词 `下雨天 南拳妈妈` 搜网易云，第一条即命中
「下雨天 南拳妈妈（下雨天了怎么办）」。脏串搜不到、干净串搜得到 —— 根因坐实。

## 2. 解法：一处纯函数，两端共用

新增 `cleanLyricQuery(title, author)`（`ui/app.js`），解析优先级（罐头拍板）：

1. **有 `《》` → 取第一个「不在括号内」的 `《》` 内容当歌名**（最强锚点；括在
   `【】`/`（）` 里的书名号是专辑名，不算）；
2. 无书名号 → 去成对括号 → 剥噪声词（画质 4K/Hi-Res、音质无损/母带、字幕、营销
   神作/超治愈、场景助眠/治愈、结构合集/串烧…）→ 在分隔符处截断取前段；
3. **顺手抽歌手**：紧邻书名号或分隔符、≤8 个 CJK 字（或 ≤3 个拉丁词）、不含数字与
   残留符号 —— **取不到就留空，宁可空也不塞错的**。

守卫（`ok=false`，不做自动兜底）：标题像 **合集 / 串烧 / 纯音乐 / 伴奏** 的，不自动配词
（那类视频本来就不该配到原唱的词），只留给「手动匹配」出手。
⚠️「歌单」**不算**合集词 —— 搬运标题里「循环歌单」很常见，算进去会误伤（第一版踩过）。

两端接的是**同一份**：
- **匹配端** `pickLyricHit`：查询词与候选标题都过 `cleanLyricQuery`；
- **关键词构造端** `crossLyric`：改用 `lyricQueryOf()`（= `cleanLyricQuery` + 脏标题时
  **丢掉 UP 主**；干净标题则歌名原样 + 保留真歌手）。

`lyricQueryOf` 的「脏/净」判据：`cleanLyricQuery().song !== 原始 title` 即视为脏。
实测样本 10/10 出干净关键词，三条合集/纯音乐全部正确判为不兜底。

## 3. 手动匹配：单入口、有词不打扰（罐头拍板）

**入口只有一个**：当前曲目**确实没有歌词**时，歌词区**正中**出现一个胶囊按钮
「找不到歌词？手动匹配」（原方案里的「歌名旁常驻小按钮」已被罐头否掉，未实现）。

- 结构：`.lyric-ask` 挂在 `.scene` 里（无词时 `.lyric-wrap` 是 `display:none`，塞不进去），
  靠 `data-haslyrics="0"` + 三态判定显形；水平起点跟歌词列 `--content-x`，**不碰封面区**。
- **三态**（`lyricState`：`loading` / `ready` / `none`）：**只有 `none` 才亮**，
  加载中不亮 —— 否则每次换曲按钮都会闪一下。曲目为空（`idle`）也不亮。
- 纯音乐（占位词被当无词）**也亮**：那类恰恰最需要手动救（罐头认可）。
- 面板：轻浮层 + 小卡（与 `.first-run` 同一套语言），预填精简结果、**歌名/歌手可手改**，
  「搜索并绑定」→ 按用户关键词搜 → 取词 → 绑定。「重新精简」把两框重置回自动结果。

**绑定持久化**：写进曲目 `raw.lyricMatch = { song, artist, keyword, at }`，
`toStoredTrack` 会把 `raw` 原样带回 `playlist.json` —— **拆窗/贴回也在**（跨文档生命周期）。
下次换曲的歌词链里，离线库没命中时**先试绑定关键词**（`runBoundFirst`），再走常规链。
执行顺序：离线库 → **绑定的关键词** → `music/lrc` → `lrc-proxy` → `ttml` → 跨源兜底。
