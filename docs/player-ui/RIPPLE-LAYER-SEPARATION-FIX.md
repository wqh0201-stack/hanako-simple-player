# 涟漪三层分离 · 检测层修复交接

日期：2026-10-12。文件：`docs/player-ui/ripple-lab-layers.html`（实验台）、
`tools/verify-lab-layers.mjs`（无头验证）。**未接生产 `ui/app.js`。**

## 一、接手的起点

画师在实验台里做「bass / 鼓点 / 镲片三层视觉分离」，卡在 **kick（鼓点）检测不可靠**：
`kickOnly` 夹具里 kick 不触发、bass 反而乱亮。他怀疑是 `fftSize` 太粗、30ms 节流
错过瞬态，建议改分析链路配置。

结论：**他怀疑的两条都不是根因。** 分析链路本身（fftSize 4096、captureStream）是对的。

## 二、真正的问题（按发现顺序）

### 1. `var lowOn` 被声明两次（现场 bug）

判据段里有**两句** `var lowOn=`：第 618 行新写的 `var lowOn=kickOn;`，
第 630 行旧逻辑残留的 `var lowOn=(谱通量...)`。同作用域 `var` 重复声明，后者胜，
把时域突发检测算出的 `kickOn` 整个覆盖掉。落波读到的永远是旧那条基于谱通量的条件，
而谱通量在此配置下恒为 0 —— 所以 kick 永不触发。
（画师探针里看到的「`kickOn=true` 而 `lowOn=false`」就是这个。）

### 2. `normE` 归一化函数饱和（真 bug）

`normE(e)=(10·log₁₀(e)+58)/38` 在 `e≥0.01` 就顶到 1。底鼓的 fast/slow 包络双双越过 0.01，
两个都饱和成 1，相减恒为 0 —— 「时域突发」这个量从根上失效。
他用更弱的夹具测到过 burst=0.166，一上真实响度就被压死，所以没暴露。

### 3. 判据选错：peakiness 在真实混音里不成立

「bass 有音高、底鼓无音高 → 用谱峰突出度分开」这个假设**只对合成夹具成立**。
真底鼓是 55→~100Hz 的滑音正弦 + 击打瞬态，**有**明显的谱峰；而混音里 bass 的窄峰会把
`peak/mean` 钉在 1.0，两者根本不重叠可分。实测：真机曲目上 kick 帧与 bass 帧的 pk 都是 1.0。

### 4. 30ms 读取节流（真问题，但非根因）

`if(now-readAt<30)return;` 让底鼓的瞬态峰值常落在两次读之间。已去掉，改逐帧读。

## 三、修好的判据（最终）

| 层 | 判据 |
|---|---|
| **bass** | 绝对能量过地板 **且** 持续基线 `slow` 在线 **且** `pk>0.60` **且** 非瞬态 |
| **kick** | 快/慢能量比 `ratio>1.9`（实测底鼓 3~8，连奏 bass ~1.3）**且** 绝对能量过地板；kick 成立后 `postKick=280ms` 内不认 bass |
| **军鼓/钢琴** | 中频能量地板 + `ratio>1.45` + 谱通量比 >1.6 |
| **镲片** | 高频能量地板（**关键**：噪声地板上 ratio 能到 3.6 但能量只有 1e-5）+ 谱通量比 |

**慢基线时间常数 0.4s → 1.4s**：这是数据选出来的，不是拍的。
更长的基线让持续 bass 的背景更平，kick 的瞬时尖峰更凸显。
实测（真机+合成同时改善）：0.25s → kick 全灭；0.4s → 真机 kick 28；0.7s → 32；1.4s → 37。

**阈值滑杆接回逻辑**：三个面板滑杆的 `thresh` 通过 `sens = threshBase/thresh` 缩放各层
能量地板（默认位 = 校准值），滑块不再是摆设。

## 六、bass 改「只出立体光波、不出描边等高线」（2026-10-12，第二轮）

罐头反馈原话：「我要的是那种立体的，就像涟漪激发的那一圈光波波。
但是把一条一条等高线去掉的样子。」

**根因**：bass 触发走 `dropKind('bass',…)`，塞进和鼓点**同一个 `waves` 队列**；
绘制循环只认 `high/low/mid`，**没有 bass 分支**，bass 掉进 else，用和鼓点**同一个颜色**
描边画同心环 —— 这就是「bass 也有等高线」的来源。

**正确改法（只做减法，别多改）**：
- 绘制循环里加一行 `if(kind==='bass')continue;` —— bass 不再被描边。
- 保留上一版的 `paintFieldGlow`（高度场光照）：bass 仍往高度场推能量，
  相邻波前干涉出立体光波 —— 这才是「涟漪激发的那圈光波波」。
- bass 仍走 `dropKind`（寿命/上限等逻辑复用），只是绘制时跳过。

**踩的坑（重要，别再犯）**：第一版改成了「平面径向渐变光斑」（`paintBassHalo`），
罐头回「怎么改成了一个在底部移来移去的光斑」。立体光波 ≠ 平面光斑：
前者是**高度场干涉出的明暗光**，后者是叠加的静态旋转渐变，没有起伏与干涉。
**只去描边，不动光照本身。**

**验收**：`node tools/verify-lab-layers.mjs` **12/12**（新增两条源码级守卫：
`bass 绘制被 continue 跳过（不出描边）` / `bass 仍经 dropKind 推高度场（出光波）`）。
截图：`steady-bass` = 立体光波无描边；`kicks` = 清晰同心环；深浅两底均成立。

## 七、诚实的边界（未解决）

**「持续 bass 与被鼓同时响」的极端情形仍分不开。** 当 bass 在低频段与底鼓**等响**时
（合成 `kick0.6/bass0.28` 那档），bass 的持续能量把 ratio 压到与 kick 瞬态重叠，kick 触发数掉到 2。
真实音乐里底鼓通常是低频最响的元素，所以真机曲目没问题；这是信号本身的分辨极限，
生产版 `ui/app.js` 同样存在。要根治需更细的谱形判据（如低频包络的**谐波结构**），
超出本轮范围。
