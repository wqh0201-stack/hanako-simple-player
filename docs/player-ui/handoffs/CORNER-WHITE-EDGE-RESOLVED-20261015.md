# 记录：独立窗 / 卡片四角白边 —— 已由应用侧自行修复（无需提交上游）

> 原拟作为 Hana 承载层反馈提交。**结论于 2026-10-15 被 Windows 实机推翻：问题不在承载层，全部由应用自己的自画圆角造成。**
> 本文件改为留档，说明为什么不用再往上反馈，以及当时的排查过程（含两个被证伪的方向，避免日后重踩）。

## 一句话

App 在「浅色主题 + 深色内容」下四角露浅色底，**是应用自己画的那道圆角 + 垫层造成的，与宿主承载层无关**。
Windows 实机验证：去掉自画圆角后四角白边**完全消失**，卡片形态与独立窗形态都适用。

## 根因

```css
.frame  { background: var(--hk-surface); }   /* 垫在角上 */
.player { border-radius: 14px 14px 0 0; }    /* 自画的顶角 */
```

- `.player` 自画 14px 顶角，切掉的三角由 `.frame` 的 `--hk-surface` 垫上；
- 浅色主题（warm-paper）下 `--hk-surface` = `#FCFAF5`，接近纯白；
- 压在深色封面上，那块垫层就从四角露出来 —— 即「白牙」；
- **宿主本身就会裁卡面**（`edge-to-edge` 落到 `hostDrawsPanel: false` / `frameOwner: "none"`），
  应用再画一道是多余的，而且这道多余的圆角恰恰把垫层从角上暴露了出来。

## 修法与验证

```css
/* 圆角全部交给宿主，App 一个角都不画。 */
```

- 无头渲染（1040×780，强制深色舞台）：左上角从**第一个像素**起就是舞台色。
  改前 (0,0)~(3,3) = `#FCFAF5`，(4,4) 才落到舞台色。
- 卡片形态像素回归（465×930，浅色主题 + 深底封面）：diff **114 像素（占画面 0.026%）**，
  **100% 落在顶部四角 14px 三角区内**，非角区 0 像素。方向正确 ——
  左上角 (0,0) 由 `252,250,245`（白牙）变为 `73,78,84`（深色封面内容），
  即深色内容填满了原来垫层露出的那块，不是整片乱变。
- 构建号 **1003131704**，已 reload。
- 验收：verify-ui 427/427、后端 132/132 全绿。

## 曾经的误判与两个被证伪的方向

排查中途曾误判为「分两层，第二层在宿主承载层、应用够不到」，并据此起草了上游反馈。
那个判断错在：只做了「窗口形态不画圆角」的半改，看到白边**变小但未消失**，就推断剩余部分来自承载层。
实际上是因为**卡片形态也中招**，而当时只改了窗口形态。

另外两个方向经核实不成立（若日后有人重提，可直接引用）：

1. **「升级 Electron 到 43 可修」—— 不成立。**
   Electron #51278（frameless 全屏白边）的修复 PR #51287 只进了 **43.0.0**；
   逐个核对 42.0.0/42.0.1/42.1.0/42.1.1/42.2.0/42.2.1/42.3.0/42.3.1 的 release notes，均无该修复。
   且该 issue 是**全屏 + Win11** 场景，与「非全屏 + Win10」不重合；42.x 上无同类报告。
2. **「Win11 用 `roundedCorners`」 —— 对 Win10 无意义。**
   Electron 文档：该选项在 Windows 11 Build 22000 之前无效。Win10 19045 远低于门槛。
