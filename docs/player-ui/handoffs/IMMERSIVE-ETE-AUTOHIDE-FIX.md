# 沉浸底栏出窗计时修正

2026-10-11，用户反馈从封面内容区直接移出窗口，超过六秒底栏也未隐藏。随后确认隐藏延时改为 **3 秒**；原简报中的 5 秒规则由本次确认替代。

开工基线：`hana-simple` / `f9a7161`，构建 `1003131647`，工作树干净。安装目录与当时宿主快照均为同一构建，排除了旧部署这一原因。本次构建为 `1003131649`，version 仍为 1.0.0；不改 manifest、后端或播放器布局。

## 本次改动

原代码将任何“坐标仍在视口内部”的根节点 `pointerleave` 全部忽略。这会吞掉携带最后一个内容区坐标、或全零位置的离开通知。现在普通内容区的根节点离开事件能启动计时，只有顶部 40px 且带有效位置的事件继续作为宿主 Chrome 交接保护。没有改变“移出整个窗口”的规则，也没有加入窗内静止隐藏。

键盘操作后，焦点可以一直留在按钮上。旧代码只在鼠标按下时清除键盘保护；现在鼠标实际移回内容区也结束旧保护，避免用户已回到鼠标操作、底栏却被残留按钮焦点永久锁住。继续用键盘操作时仍保持可见。

所有出窗、恢复播放、操作结束后重新计时的延时统一为 **3000ms**。进入、点击、键盘输入、重新获得焦点立即唤回；暂停、搜索、拖动、菜单、音量浮层及歌词对齐的保护继续保留。

## 验证范围

UI 验收保留原有断言，新增最后内容区坐标离开、全零离开、键盘后恢复鼠标操作共五条回归；真实计时验证改为三秒前可见、三秒后隐藏。新增离开坐标用浏览器事件模拟，不能冒充已捕获到的 Hana 原生事件。

结果：UI **212/212**，布局 **12/12**，窄卡 **4/4**，0 运行时错误；后端 **22/22**。最终源码另跑 ETE 定向复核 **41/41**，包含客户区坐标归零但屏幕坐标仍有效的离开事件。

本次源码修正尚需整包同步 UI 与正式 reload，之后验证实际窗口。尤其是宿主顶部按钮接管指针后直接出窗，iframe 可能没有后续通知；顶部坐标过滤仍只是 App 内的保护，不能替代官方原生窗口进出信号。没有读取宿主私有 DOM 或使用非公开桥。
