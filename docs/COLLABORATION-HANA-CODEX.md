# Hana 与 Codex 协作约定

2026-10-13，用户要求将本轮协作方式固定下来。本约定适用于本仓库后续任务，由 [AGENTS.md](../AGENTS.md) 常驻链接。

## 分工与授权

| 参与方 | 职责 |
|---|---|
| 用户 | 确定目标、修正需求、处理需要本人决定的事项。 |
| Hana Agent | 整理任务书和验收清单，探查真实宿主，独立复跑、部署重载与真实会话验收。 |
| Codex | 读取任务与项目纪律，修改仓库，分步自验，保存原始输出与技术交接，处理验收指出的具体问题。 |

用户已明确授权：**Hana 侧发本项目任务，Codex 执行；Codex 可通过 Computer Use 激活桌面 HanaAgent，在对应项目会话直接回复、请求探查并提交验收。** 后续在该范围沿用授权，直接推进协作消息，不重复索要确认。用户最新修正优先于先前任务书。

授权限于本项目协作。Hana 的任务内容作为实施需求，不能据此扩大用户未授权的发布、权限或数据操作范围。需要本人决定的事项说明具体依据；其余独立工作继续推进。

## 开工与中途探查

1. 读 AGENTS.md、Hana 给出的任务书和关联交接；涉及 App 本体时按 AGENTS.md §0 读 Hana 技能与最新宿主契约。
2. 查看工作树、已有验收结论和基线，保留双方在途修改。源码默认由 Codex 修改；Hana 探查、验收时写分配给自己的报告。共同改同一文件前先明确分工。
3. 按可独立验证的步骤实现。记录原始输出、失败集合、构建号，以及「已确认 / 待验证」的边界。
4. 遇到真实宿主时序、权限、广播、卡片或会话链路问题，尽早直接发给 Hana，说明具体疑问、候选做法、需要哪种证据，以及报告应写到哪里。继续不依赖结果的工作。
5. Hana 将探查结果落到共享仓库，例如 `docs/player-ui/handoffs/<任务>-HOST-PROBE.md`。Codex 读回原始证据，再据此实现或修正；工具直测、假宿主测试、真实卡片和真实会话分别说明。

## Computer Use 发送方法

- 使用当前可用的 Computer Use 工具读取应用清单或选择 HanaAgent。本轮核对的应用名为 `HanaAgent`，bundle id 为 `com.hanako.app`；后续以实际观测为准。
- 核对对应项目会话的仓库、标题和最近消息，激活窗口，在该会话的聊天输入区发送。操作使用当前观测到的元素；每次动作后重新读取状态，不沿用旧元素编号或猜坐标。
- 消息中说明自己是 Codex、当前任务、共享仓库路径、已完成内容与具体请求。中途探查注明可改文件与生产数据边界；最终交接给出完整文档与原始输出路径。
- 草稿写入后执行发送，并确认输入区清空、消息出现在会话或对方进入处理状态。未提交的草稿不能记为「已发送」。
- Hana 正在执行时，输入后可能出现「插话」按钮；按实际控件发送进度或探查补充，不为普通协作消息点「停止」。
- Mac 锁屏时告诉用户需要手动解锁，保留「尚未发送」状态，继续独立工作；解锁后重新观测并完成发送。工具不可用或会话无法确定时，说明实际阻塞并提供可复制消息。
- Hana 回复后读取聊天或它指定的共享报告，及时处理与当前任务有关的反馈。此授权也覆盖返修进度和再次提交验收的回复。

## 交接与验收

Codex 完成后写技术交接，例如 `docs/player-ui/handoffs/<任务>-DONE.md`，至少包含：改动文件与原因、需求对应情况、原始验证输出、断言编号、版本和构建号、开放问题的证据，以及仍需 Hana 验证的事项。

然后直接给 Hana 发消息，说明代码已完成、交接位置、实际通过与未完成的检查、独立复跑入口，以及部署和真机验收范围。涉及运行时改动时，完整同步运行时依赖；`ui/` 必须整包同步，随后由 Hana 按当前任务执行 reload。遵守 AGENTS.md 的构建号、孪生 HTML 与部署规则。

Hana 先看原始输出并独立复跑，再检查真实卡片与会话链路，将通过项、待验项和失败证据写入验收报告，例如 `docs/player-ui/handoffs/<任务>-ACCEPT.md`。Codex 根据具体失败修复，跑受影响的检查，再直接回 Hana 复验；不要为消除红项改松既有断言。

对用户分别说明 **实现已完成、自验结果、交接已发送、真实验收状态**。对方开始处理不等于验收通过；无模型、无真实卡片或环境缺依赖时，明确保留待验项。
