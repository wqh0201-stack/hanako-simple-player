## 2. 已核实的现状（允许基于证据修正实现方案）

### 当前封面链路

- `ui/app.js` 中 `coverKey` / `cleanCoverQuery` / `pickCoverMatch`（约 6821 起）独立于歌词清洗。
- 目前只按 `歌手 空格-空格 歌名` 拆分；`周杰伦-稻香`、倒序、前导序号、`【无损】`、游离 MV 等兼容差。
- 当前先在原始标题上检测 Live/现场/合集等词并拒绝，之后才清洗；候选又要求仅有一个歌手，导致版本、合唱等一律排除。
- `startCoverFill`：指定一个歌手 → 枚举其所有专辑 → 取每张专辑曲目 → 逐首精确匹配。任一专辑失败会导致本轮不提交。
- `guessCoverArtist` 从歌单/视频标题兜底只硬编码周杰伦、陶喆、Aimer。
- `coverTargets` 保护已匹配/已有非 B站封面，按 B站稳定 ID 去重。
- 单曲 `getTrackCover`（约 6957 起）直接优先拿 `t.author`；缺歌手时提示「先补全歌手或用歌单级补全封面」并 return。
- `applyCoverMatch` / `restoreCovers` 保留原图和来源绑定，同稳定 ID 的未删除副本同步；单曲支持任意平台，恢复也支持任意平台。

### 可复用能力

## 3. 匹配要求：不要只堆正则，也不要用模糊相似度硬选

### A. 提取身份而非破坏性改名

内部区分歌名、歌手线索、版本、装饰；允许少量有证据的解析候选：

- 支持 `歌手-歌名`、带空格分隔、`歌名 - 歌手` 等常见写法。横杠两边谁是歌手不能只靠位置猜，需结合已知歌手/官方身份或候选元数据验证。
- 兼容曲目前缀编号（带明确编号结构）、`【无损音质】`、`[1080P]`、MV/PV 等装饰。不能删掉真实歌名中的数字、横杠、斜线、括号或恰好同名的词。
- `《》` 是重要锚点，但要避免把广告括号里的专辑名当歌名。
- Live、翻唱、Remix、伴奏、钢琴版等是身份/版本线索；有明确同版本候选时可匹配，不能因为一个词出现在原串就一律拒绝，也不能删掉版本词后自动套原版。
- 真正的串烧/多首联唱无法确定对应单曲时继续保留原图。合集总标题不应自动让可明确识别的单首分 P 失去匹配机会。
- 短歌名/单字歌名必须严格；不要因为中文包含关系或编辑距离接近就自动接受。

### B. 歌手身份

- 明确的单曲身份/用户已确认线索优先；单曲标题可证实的歌手、可靠平台音乐元数据其次。B站 UP 主不可直接充当歌手。
- 歌单填写歌手是缺省线索，不能覆盖曲目明确标出的其他歌手。允许逐首识别和匹配，不把混合歌单全套给一人。
- 通用正式名/别名解析代替三人兜底限制；显式别名解析成同一官方 ID 后，不应在后续名称比较层再次错误拒绝。
- 合唱不是自动拒绝理由：确认参加歌手和版本一致才可用；不确定则保留。
- 缺少可靠歌手时，可查询候选帮助识别，但不能仅凭搜索首条/当前页唯一同名结果就断言身份正确。

### C. 查询与自动决策

- 优先复用有效绑定/缓存/已读曲库；不足时用少量歌名＋歌手查询补候选，不必总先扫完整个歌手专辑。
- 查询要有界、缓存、去重与节流。无需新平台、无需扩权。不要把瞬时网络错误缓存成永久无结果。
- 自动替换需歌名、歌手身份、版本无冲突且候选足够明确；歌手/版本硬冲突不得被其他相似度加分抵消。
- 原始正式专辑等封面优先规则，只在身份/版本已经确定后使用；不要仅凭最早日期把另一录音版本当原版。
- 单项无结果或网络失败不拖垮其他已可靠匹配项；保存失败和取消继续具备清楚、可验证的回退/未提交语义，不留半写状态。

## 4. 批量与单曲交互

### 批量

要求：

- X/Y 按去重后的实际目标计数，结果与落盘一致；已保护的自选封面、已匹配曲目不虚报为本轮失败；全部已齐、零目标、全部未匹配、部分网络失败等分别处理。
- 有未补项时展示一次易读的最终汇总（可沿用现有面板持久结果，必要时轻提示，但不要只用一闪而过的 toast 承载全部引导）。不逐曲弹错，不新增结果页/候选选择器。
- 补全只动封面与匹配元数据，原名、歌曲列表顺序、播放/歌词不变。

### 单曲兜底

- `⋯ → 获取此曲封面` 沿用；正常可自动命中的仍尽量直接完成。
- 缺歌手或自动未命中时，在当前曲目的轻量面板/弹层预填解析出的歌名、歌手，允许用户补填或修正并重试。不要求先去「补全歌手」，不跳回整歌单补全。
- 无歌手也有可操作的输入和提交入口；请求失败后保留输入可再试。不能只换一句 toast 仍然 return，也不要无限 spinner/按钮永远禁用。
- 此处不做封面候选列表、不做新管理页。仍有歧义时留原图并提示可修正关键词，不猜一个替换。
- 手动输入只服务本曲封面匹配，不擅自改写歌曲标题、author 或歌词绑定。成功的手动封面身份绑定可复用且应受自动批量保护；恢复原封面能力继续可用。
- 与批量同时运行、目标已移除、迟到请求等竞态按当前稳定 ID/uid 核对，不串曲、不覆盖其他曲。
