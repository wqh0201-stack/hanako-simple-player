## 本轮决策（统筹已选定，不需要用户再选）

### 1. 全实例统一节流

- 网易云封面元数据的 artist/search/albums/album 全部共用一个后端频率闸门。
- **真实外网请求起始时间至少间隔 2000ms**；所有重试也必须经过同一闸门，不能为重试绕开。多个窗口/批量/单曲不能各自独立放行。
- 成功缓存命中、同参数在途合并继续有效，缓存命中不应白等 2 秒，也不触发外网。
- 不安装新依赖，不扩 host/权限，不更换音源，不接 cookie/代理；不改变其他播放/搜索链路的策略。

### 2. 405 后全局冷却与有界恢复

- 识别上游业务 code 405 / 实际 HTTP 405 的临时拒绝；HTTP 429 也宜进入相同保护，不混淆 app 本地歌手不存在的 404。
- 出现拒绝后，网易云封面链路**全局冷却 60 秒**；冷却期间不能因后续歌曲/另一窗口/反复点击继续发真实请求，可正常读已有成功缓存。
- 结构化向前端提供临时拒绝标志、原上游 code、请求阶段与剩余冷却时长（如 retryAfterMs）。不拿一般「歌名不符」文案代替；失败不是成功结果，不持久缓存成空数据。
- 批量：第一次拒绝时暂停而不是连刷后面的几十首，显示冷却状态；冷却后最多一次恢复试探（可重试当前曲，成功阶段应复用缓存）。同一本轮再次被拒则停止继续请求，不无限等待/试探，不把未处理的剩余几十首都计为请求失败。
- 自动保护停止时，可按现有正常保存链路提交之前已确认、已探图成功的 ready 项，并明确剩余尚未补；保存失败仍回滚。**用户手动点停止**的取消语义保持原样，不将取消误当自动保护停止而偷偷提交。
- 冷却等待必须响应停止/关闭的 AbortSignal，不能让用户点击停止后再挂 60 秒；清理 timer/listener，busy 状态要能恢复。
- 多窗口恢复探测仍受后端统一闸门/冷却控制，不能在 60 秒到点时同时放行一批积压请求。

### 3. 单曲提示与重试

- 临时拒绝时保留用户输入，提示例如「上游暂时拒绝请求，约 N 秒后可重试；已保留歌名和歌手」，不让用户误以为继续改词能解决。
- 冷却内重复点也不得触发真实外网请求；按钮/提示最终能恢复，不能永久禁用或无限 spinner。不新增设置页、候选选择器或复杂进度管理。
- 错误阶段和业务码保留；修复语义是降低请求密度与抑制连败，不能承诺 405 已完全根治。
