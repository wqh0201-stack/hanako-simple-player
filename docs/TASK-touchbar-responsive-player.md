## 1. 任务与资料优先级

给播放器增加一种适用于**低高度、横向长条**容器的布局。它区别于现有竖长卡，也不能简单等同于现有 `compact`。从大卡跨入横条时有一次短过渡；横条内部继续响应可用宽度。

本轮只整理任务和视觉资源，没有修改播放器运行代码、安装、重载或发布。用户准备另开对话接力，实现者收到本任务后开始实施。

## 2. 已确认的静态布局

示意顺序：`独立封面  间隔  [歌名/歌手固定区 | 歌词或控件弹性区]`。方括号整体是彩色进度背景。

| 部位 | 必须实现的行为 |
|---|---|
| 封面 | 左边独立的圆角正方形，与右侧彩色条有清楚间隔；不能被条包住或覆盖。横条内宽度变化时，封面宽高固定，不能缩小。使用真实当前歌曲封面。 |
| 彩色条 | 小圆角的长矩形，借鉴 Touch Bar；不要做成两端半圆的药丸。进度区域加粗为整个主体背景，歌名、歌手、歌词、控件在其上。上下留白。 |
| 歌名/歌手 | 在彩色条内靠左，歌名上、歌手下。固定宽度容器，单行省略号；不能因长标题挤走控件，也不能靠缩字号或跑马灯解决。 |
| 歌词 | 静听时显示一行当前歌词，随歌曲逐句更新；占用右侧弹性区域，长句合理截断。没有歌词时安静降级，不能显示假歌词或永久加载。 |
| 控件 | 鼠标进入交互区域后歌词隐藏，控件在同一区域出现；紧接身份区向左排列，不悬在整窗最右侧。歌名/歌手仍保留。 |
| 时间 | 当前时间在彩色条内左下角，总时间在条内右下角；仅交互态显示。为时间留独立基线，不叠歌手、按钮或音量条。 |
| 根容器 | 跟随宿主实际尺寸与主题。根 `.player` 四角仍为 0，由宿主裁切；小圆角仅用于内部封面、彩色条和控件。 |

参考图有静听、悬停、窄宽度等状态。用户没有指定唯一一张为唯一皮肤。可采用“通透稿的多色底 + 分段稿的控件组织”，并用深色稿校准 Hana 深色主题；这只是实施建议，不能另加三套外观设置。

尺寸尚未锁为产品常量：可先以封面 **64×64 CSS px**、身份区约 **128px**、内部圆角约 **5–8px** 起步，结合真实宿主微调。确定后，**同一横条布局内封面与身份区必须保持固定尺寸**，文字至少 11px。图中的 64/112/150 等数字不同时具备约束力。按钮点击区、容器最小宽度和宿主安全区要一并核算，不能强塞到放不下的宽度里。

## 3. 已确认的交互

常用控件：上一首、播放/暂停、下一首、播放模式（含随机）、喜欢、音量。沿用现有播放语义与状态。**横条不放歌单、队列、搜索、曲库入口**；其他布局已有的这些功能保留。

- 静听态：歌词显示；控件、两个时间隐藏。隐藏控件不能残留不可见点击拦截。
- 悬停或键盘交互态：歌词退场，控件出现，时间在条内下角出现。控制区域包含其展开部分，指针从音量按钮移到音量滑杆不能意外恢复歌词。
- 音量由**点击喇叭**展开，滑杆从按钮**向右延伸**，有短促、柔和的展开动效；再次点击收起。不能沿用原有悬停竖向音量弹层，也不要让音量面板替换整条控件。
- 拖动音量、拖动进度或焦点停留期间保持交互态；指针离开且交互结束后恢复歌词。收起规则需覆盖外部点击、Escape、焦点转移；不得吞掉正常按钮操作。
- 为键盘和无悬停设备提供等价的显式入口；可见焦点、读屏名称、滑杆键盘调节必须可用。不能要求用户先用鼠标才能 Tab 到控件。
- 背景承担真实歌曲进度展示和拖动定位。按钮、标题链接、音量等交互优先，不能因为事件冒泡误 seek；进度手柄可在交互时出现，不要用巨大圆球压住内容。
- 长标题仍可通过已有机制获知完整内容；保留现有标题/歌手/来源/封面操作的有效入口。新布局隐藏某个旧入口时，只影响横条展示，不能删掉原功能。
- 未知时长、加载中、暂停、空列表、封面失败都要有稳定状态；不做除零或 `NaN` 进度。是否可 seek 服从当前音源能力。

宽度不足时先压缩歌词/彩色条的弹性区域，再调整次要控件的可见组合。可用一个轻量次级操作组容纳模式、喜欢等，不能因此加入歌单功能。播放/暂停始终可达；上一首、下一首、模式、喜欢、音量仍须有可发现入口。**不得缩封面、缩字、把标题区变成无限弹性区，或通过音量展开把封面和身份区挤走。**

## 4. 封面多色进度背景

用户最后确认的是“提取很多封面颜色”的观感，不是任意指定一条双色线性渐变。参考图有青、暖黄、粉橙等局部色区与柔和纹理。当前 `dominantColor()` 只给出单个主色，仅复用 `--ambient-color` 不足以还原。

实施目标：从封面生成空间上有层次的多色场，可用低分辨率封面取样/模糊纹理与多处柔和色团组合；保留不同位置的颜色，不把整张图平均成一团泥色。用明暗遮罩保证文字、图标和时间清楚可读，颜色主要来自封面，结构和可读性跟随 Hana 主题。

进度按比例揭示/遮罩**完整长度的同一色场**：从 20% 拖到 80% 时颜色区域不能随百分比重新拉伸、跳色或重采样；未播放区域保持较弱的主题底或弱色场，已播放区有明确差异。0%、接近 0、50%、100% 均需检查裁切与圆角。

封面解码、采色和模糊只在封面变化时执行并缓存，不能放入逐帧播放或 resize 路径。复用现有封面代理/CORS 方案；快速切歌后丢弃旧异步结果，避免上一首颜色覆盖下一首。彩色、灰度、缺图、失败图都需确定的降级。默认不引入新域名、权限、重型库或后台服务。

新增横条专用颜色数据，不改变大卡现有环境主色与音频涟漪配色语义。不要为复刻横条而把整张模糊照片重新铺回其他布局。AI 图中的星点、水光是风格参考，不表示采色必然能生成这些纹理；少量纹理是可选项，不要求像素级复刻，也不应增加持续高负载特效。

## 5. 核心：断点切换与横条内部响应式是两件事

用户最后纠正：

> “播放器调整窗口是能随时停下的……一定是得有一个瞬间，从大卡变成长条横卡的布局，这时候触发变换动画，然后再就是长条横卡内部的缩放问题。”

### 5.1 布局必须离散落定

1. 用宿主实际分配的可用宽高选择完整布局。不是把“窗口拖到哪”映射成“大卡变横条动画播放到百分之几”。
2. **跨过断点时，立即提交目标布局状态**；随后用独立时间轴完成一次短过渡。用户此刻松开拖拽，动画照常结束，最终必须是一张完整的卡或一根完整的横条。
3. 同一布局内仅正常响应尺寸变化，不在每次 `ResizeObserver` 回调重播整套变形。横条内封面/身份区/字号不变，弹性区和控件组合适配宽度。
4. 采用进入与退出不同的阈值，避免临界区反复闪切。例如“高度 ≤156 进入、≥184 退出”仅是讨论用示例，**不是生产断点**。需要结合可用宽度、比例、内容最小包络和宿主右上 100×40 安全区实测确定；长竖卡不能因宽度单项误判成横条。
5. 低高度但宽度不足时，要有实测可用的完整降级布局或尊重宿主已支持的最小尺寸；不能回到一个已被裁掉按钮的高大卡，也不能宣称支持未验证的任意尺寸。任务交接记录实际支持包络与宿主边界。
6. 首次挂载或宿主暂时给出 0 尺寸时，不据此切成横条；按现有生命周期处理，等有效预算。

### 5.2 过渡动画建议与约束

- 可用封面、身份区、当前歌词、色场的视觉连续性建立过渡；其他内容淡入淡出。建议约 **220–350ms**，曲线轻柔，具体时长可微调。
- 动画只影响应用内容的呈现，根容器始终使用宿主当前宽高；不能为了演出自行驱动窗口尺寸、调用 resize 抢夺宿主尺寸或给容器假高度。
- 动画开始后同布局继续变宽/变窄：目标几何更新到最新尺寸，不能反复重置时钟而永远结束不了。
- 动画中反向跨断点：取消旧目标，从当前可见状态朝新目标过渡；不排队，不让旧回调覆盖新布局，不突然跳回最初几何。
- 尊重 reduced motion；可改为短淡变或直接落定。不可见/卸载停止相关循环，恢复时重新核对最新有效尺寸。
- 布局落到静止鼠标下面时，避免立即被误当作主动悬停而切走歌词；通过新的指针活动或焦点交互进入控件态。
- 同一文档缩放期间，歌曲、播放时间、音量、喜欢、模式连续保持；不能重建 audio、重接媒体图、暂停或重置歌曲。现有迁窗架构如有独立限制，单独记录，不把本任务扩成音频架构重构。

可参考的状态流程：`读取有效尺寸 → 判断目标布局（含滞回） → 若跨布局则立即提交状态并启动/反向重定向时间动画 → 若未跨布局只更新响应式几何 → 动画按时间落定`。这个流程与 seek/歌词时钟、音量展开状态分别维护。

此前“用滑块控制大卡到横条连续变形进度”的漂亮演示已被用户否定，**不得作为实现模型**。本轮没有将旧 HTML 演示复制为生产模板；应在现有 App 中实现上述状态与动效。

## 6. 现有代码入口与实现边界

以下行号是任务整理时的定位提示，开工以搜索到的现状为准：

| 入口 | 现状与注意事项 |
|---|---|
| `ui/app.js` · `applyLayout()`（约7797行） | 当前先按 `w>=720` 判 wide，再按高度判 compact/long；会漏掉宽而矮的横条。新增规则应审查优先级，不能只改一个 CSS 媒体查询。 |
| `arrangeControls()`（约7760行） | 现有控件 FLIP 与中心布局有自己的340ms动画；避免与新形态动画、音量展开争抢 transform/位置。 |
| `coverSrc()`（约1489行）、`ambientCache`、`dominantColor()`（约1653行）、`applyAmbient()`（约1792行） | 复用封面路径与缓存治理，新增横条多色场；保留其他形态主色机制。 |
| `volPopShown` / `openVolPop()` 等（约5137行） | 原有竖向音量弹层只在原布局保留；新条应有点击向右展开的状态和事件治理。 |
| `ui/style.css` | 审查 `data-layout`、`data-bar`、`data-ctl`、seek、controls、volume、cover、歌词相关选择器；防止旧布局规则串入。 |
| `ui/index.html` / `ui/standalone.html` | 同步 DOM、稳定id、SVG图标；除 body 的 `data-shell` 外保持一致。 |

新增布局可用独立命名或专门属性，名称由实现者选择；必须通查所有布局枚举、`LYRIC_VIEW`、歌词可见性/绘制预算、页面/抽屉状态、诊断和测试选择器，避免新状态走未知分支。进入横条时如何收起旧搜索/歌单/歌词面板、退出后如何恢复，需有明确一致策略并验证；不能留下遮住横条的不可见交互层。

优先复用现有 audio 和播放事件、收藏和模式状态、seek、封面数据，不另造第二套播放器。必须保留当前标题/来源交互、封面获取与恢复、列表搜索、歌词同步、随机上一首语义、音频所有权和生命周期优化。不要顺带重构后端、改音源、修改用户数据、改许可证或外部发布。

实现遵守项目 ES5/无构建约束；主题 CSS 变量走现有桥接，不覆盖宿主同名变量；SVG 线描图标、字号≥11px、不用 `position:fixed`、直接 localStorage 或 window.open。根 `.player` 不补圆角（以 AGENTS §6 和 PITFALLS 为准）。

## 7. 实施步骤与证据

1. **复核现状与宿主尺寸**：记录 HEAD/工作树/版本/构建及当前基线。先核对宿主支持的浅横条尺寸、尺寸事件、控制安全区和挂载时序；需要时按协作约定请求 Hana 实测，报告落 `player-ui/handoffs/TOUCHBAR-HOST-PROBE.md`。其余独立代码工作继续。
2. **先做完整布局**：实现稳定静听态、交互态、真实播放和小宽度降级，确认固定封面与身份区。再接多色场和完整进度交互，避免只做一张假封面静态稿。
3. **再做离散切换与短过渡**：在已验证的完整布局之间加动效，覆盖停止拖拽、反向跨断点、滞回、持续缩放和 reduced motion。
4. **自验与报告**：执行下面的针对性验收，保存输出、截图/录像、失败集合；运行现有适用检查，不能为新布局把无关断言放松。现有“控件均常驻可见”等断言如与新条交互态冲突，应明确区分布局/状态并补等价可达性检查。
5. **交接 Hana**：写完成交接与原始证据，按协作约定发送。运行时代码完成后 bump build、保持孪生 HTML、整包同步 `ui/` 后 reload，由 Hana 独立复跑与真实宿主验收。不要把 mock、无头测试、工具直测当成真实会话验收。

本轮仅整理文档，无需 bump build 或运行整套播放器测试。下一轮修改运行时后，至少按改动范围运行 `tools/verify-ui.mjs` 和相关后端/音频所有权/封面检查；先检查脚本说明与环境，再选实际命令和证据目录。历史报告中的通过数不是本次结果。

| TB09 边界/反转 | B_in/B_out 两侧与滞回区多次往返；动画中迅速反向、持续调整宽高；无闪切、旧回调回滚、队列积压或永不结束。 |
| TB10 条内适配 | 入条后继续改宽度，仅弹性区/控件组合变化，不重播大变形；长竖卡未误判横条，wide 的矮窗口能正确进入。尺寸停在边界前后均完整可用。 |
| TB11 音频连续 | 同一文档播放时缩放往返，歌曲/进度持续、无重建 audio/重播/音量与模式丢失；seek/音量拖动途中变尺寸也能正常结束。 |
| TB12 生命周期 | 首开0尺寸、挂载/隐藏/恢复、窗口与聊天卡片、reduced motion 都按现有契约工作；无新长期逐帧采色、同步布局抖动或隐藏后台动画。 |
| TB13 主题与可访问 | 跟随 Hana 的浅/深主题切换，封面颜色上的文本可读；最小字号与安全区达标；键盘可主动进入控件，触屏有等价入口，悬停不会因布局落在静止鼠标下误触发。 |
| TB14 回归与宿主 | 大卡、竖长卡、compact，以及现有歌词/搜索/收藏/封面入口无回归；整包同步/reload 后，在实际宿主聊天卡片和独立窗口验收，区分未验与通过。 |

测试除正常流外需包含：超长标题/歌手/歌词、无歌词、无封面、长总时长文本、暂停、快速切歌、弹层打开时改尺寸。断言实际 `getBoundingClientRect` 与命中（如 `elementFromPoint`），不能只检查 class 或截图“看起来可用”。验证应围绕行为，不写只镜像实现的测试。
