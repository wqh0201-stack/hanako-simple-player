## 3. 共享官方歌曲身份与持久专辑索引

### 3.1 批量走索引优先

- 按可靠歌手身份分组：已确认绑定/显式标题/歌单共同上下文经官方身份验证；UP 主不当歌手。混合歌手歌单不能被缺省强套。
- 建立持久关系：artistId → albumId → tracks（官方 songId、标准名、全部参与歌手、别名、版本/发行线索、专辑信息、封面来源）。此索引不能只寄存在会被400条查询挤掉的通用请求 LRU 中。
- 先用已有索引，本地匹配；冷启动/缺失时优先拉相关正式专辑，再补必要 EP/单曲/版本专辑。每张专辑曲目表一次能解决多首，不为50/100首各自先搜一次。
- 成功建立的关系持久复用；只补新/缺失/过期专辑，允许中断后继续，不因一张失败清空已完成索引。记录覆盖范围和分页完整性，more=true 不构成未见专辑不归属的证据。
- 不为一首单曲扫描全歌手目录：单曲先索引，缺失再有界歌曲搜索。批量也只对索引仍未解决的少数曲目兜底，不退回全部逐首搜索。
- 同一歌手/专辑跨歌单复用，重复运行在有效缓存内不再发相同元数据请求。首次建库有成本，进度明确，不伪装成瞬时完成。

### 3.2 身份与版本安全

- 保留已验证的官方歌手/精确基础歌名/版本约束、正规发行分层和同族去重。不同发行 songId 不是录音冲突的充分证据；真同级冲突留原状。
- 缺省歌手表示归属线索，不等于明确声明独唱。官方专辑关系可证实的合作曲目应匹配并显示完整官方歌手；显式参与歌手/版本硬冲突仍不能接受。
- 编号、音质等装饰与真正歌名/版本分离。不能用 `cleanCoverQuery(...).song` 第一猜测直接改名，必须拿已证实的官方记录标准化。
- 正向/倒序若一侧恰好也是歌手（Complicated）继续保留1785修复；未知双向冲突不硬选。
- 同官方歌曲身份的数据缓存可共用，但不能因此合并/删除不同 B站源曲目或不同音轨，id/uid保持原样。
- 共享身份与 coverMatch、手动 lyricMatch 的用途分开：恢复原图不得顺带断开歌词/标准信息；不能把「换过封面」作为是否能补歌词/规范信息的门槛。

## 4. 一次匹配，分阶段补齐

### 4.1 标准信息（用户已授权统一）

- 对可靠匹配项统一显示/存储官方歌名、歌手，并补专辑等相关信息。既有名字被覆盖前保留最初原值（各列表副本可能不同，分别备份）；再次整理不把“已规范值”覆盖成最初备份。
- 不改播放 source/url、BV/CID、id/uid、音频文件名、顺序和收藏关系；播放中的曲目只刷新展示/媒体元信息，不重载音轨或打断播放。
- 提供同层级的「恢复原始曲目信息」动作，能恢复标题/歌手/原专辑等备份；明确与「恢复原封面」不同。备份不能只有不可操作的隐藏字段。
- 自选封面/已手动歌词受保护，但这不应导致整个曲目跳过其他未完成阶段。将“整理目标集合”与“本次是否允许替换封面”分开。

### 4.2 封面：一专辑一份有效本地缓存

- 用 albumId + 源图版本/地址哈希缓存图片，所有关联歌曲引用同一份；缓存有效且源图未变化时不重复向外网抓取。源图变化/正常清理后可重新取，不承诺永远只下载一次。
- 持久化在 App 自己数据目录，容量/单图大小有界、原子写入、失败不留损坏命中；只允许既有授权的官方图床。路由不接受任意文件路径/URL，保留认证/Content-Type等安全边界。
- 使用 App 现有 SDK/ctx.network 和资源路由契约；本地缓存图仍支持当前环境色/CORS/系统正在播放信息。Agent手工下载文件遵守downloader铁律，不裸跑下载命令。
- 原封面备份/恢复和自选封面保护继续有效。

### 4.3 歌词：直接按已确认歌曲 ID 获取与绑定

- 使用同一个官方 provider/songId，复用既有可靠取词链路，不再按被洗过的标题重新模糊搜索一次。自动绑定与用户手动 `raw.lyricMatch` 分开存储。
- **默认不覆盖已有手动词源、手动歌词和手动时间偏移**。自动流程不能直接调用会清空偏移的手动 bind 函数；先核对现有优先级与保存契约。
- 新歌词按 provider/songId 缓存（防同名和改名冲突）；兼容既有按名称的本地LRC/绑定，不删除/覆盖用户文件。规范后仍能找回原名对应的已有词。
- 同一官方歌曲跨列表/不同源复用取词数据；播放音轨和各源校准信息不因共用歌词文件而混淆。
- 无歌词/纯音乐、上游失败、版本不符分清；取词失败不阻断已有可靠信息/封面整理，不伪造成功。自动找词不等于保证B站片头/剪辑音轨逐秒对齐，保留校准入口和已有手调。

## 5. 频率与405保护（采用准备稿的已定范围）

- 网易云整理相关 artist/search/albums/album（以及新增整理取词/取图涉及同源请求）走共享调度，同源真实请求起始间隔至少 **2秒**；重试不能绕过。缓存命中不白等、不发网，多窗口不各自放行。
- 业务code405/实际HTTP405、429进入全局 **60秒冷却**；冷却期间不能因后续曲目/另一窗口/反复点再打上游，可读有效缓存。
- 批量第一次拒绝暂停，冷却结束最多一次恢复试探；同一本轮再次被拒停止继续请求，不把未处理的几十首都记请求失败，不无限循环。
- 自动保护停止可提交已验证可保存的阶段结果；用户手动停止维持清楚的取消语义，不能暗中提交。等待响应AbortSignal、timer/listener清理，busy恢复。
- 单曲保留输入、显示阶段/业务码和剩余冷却时间，不再泛泛要求用户修改关键词；重试控件最终能恢复。
- 不把405断言成已确认限流，不保证节流后彻底消失。
- 用户授权 **仅诊断时**若直连拒绝，可用 `http://127.0.0.1:7897` 做少量只读对照。按 clash-proxy 技能确认该域名实际路由，不改系统代理/节点，不将代理固化为App默认，不借此无限请求；记录不同出口结果但不凭一次成功推断根因。
